### Summary of Release-Blocking Defects (P0 / P1)
1. **P0 — Desktop Shell Compilation Failure (`frontend/src-tauri`):** Clean cargo build fails with `error[E0599]: no method named 'lock_exclusive' found for struct 'std::fs::File' in src/native_vault.rs:3891` due to an unsynchronized `Cargo.lock` and an unimported `fs4::FileExt` trait under `-D warnings`.
2. **P0 — Total Absence of Windows Binaries:** The repository contains zero Windows installers (`.exe` or `.msi`). Testing and release on Windows are completely unverified and unbuilt.
3. **P1 — Sentinel/Guardian is Warning-Only (No Real Process Enforcement):** In `crates/shinpo-shield/src/enforcer.rs:340`, `enrollment_identity_verified` is hardcoded to `false`. Sentinel cannot terminate, close, or quarantine any distracting application.
4. **P1 — Client Device API Stubs Throw Runtime Errors:** In `frontend/src/api/device.ts:51`, `requireBackendDeviceApi()` throws `Error: Sentinel device controls are not available for this local account yet` whenever the user attempts to view running processes, system stats, or quarantine rules in standalone mode.
5. **P1 — Chromium Extension Sideloading Overhead:** The browser companion is not published to web stores. Google Chrome 155+ blocks unpacked extension command-line loading (`ERR_BLOCKED_BY_CLIENT`). Testers must manually enable Developer Mode, load unpacked folders, and run elevation scripts.
6. **P1 — CI Pipeline Blindspot:** `.github/workflows/ci.yml` tests Spring Boot, React, and `shinpo-shield`, but completely omits `frontend/src-tauri` from the build and test matrix.

### 7.1 Real Enforcement vs Warning-Only
- **Status:** **FAIL (BLOCKER)**
- **Evidence:**
  In `crates/shinpo-shield/src/enforcer.rs:340`:
