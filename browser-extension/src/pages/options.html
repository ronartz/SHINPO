SHINPO Browser Companion

Setup and privacy

Pairing

The pairing code is created locally by the native host installer. It is never included in the extension source or sent to a webpage.

Focus Rules destination

HTTPS is required except for a localhost SHINPO development installation.

Why these permissions are requested

  • Native messaging: communicates only with the per-user SHINPO host.
  • Tabs and web navigation: checks top-level page addresses locally against your active focus rules; access is broad because a rule may target any website.
  • Page scripting: injects SHINPO's intervention only into a tab matched by an active rule; it does not read page text.
  • Storage: retains the pairing proof, policy snapshot, and short-lived session intervention/return addresses.
  • Alarms: refreshes policy and removes restrictions at lease expiry.

Top-level URLs are evaluated on this device; SHINPO does not upload a continuous browsing history. A restricted destination is sent to your configured SHINPO server only if you request a temporary exception. There is no cookies, downloads, webRequest, clipboard, camera, microphone, or notification permission. The YouTube content script reads route information, not page content.
